## Purpose

Дать ученику возможность сообщать об ошибках контента и тьютора и автоматически ограничивать показ упражнений с подтверждённым потоком жалоб.

## ADDED Requirements

### Requirement: Reports on learning content
Каждое упражнение и реплика тьютора MUST иметь жалобу с причиной (ответ/перевод/непонятно/звук/другое) и комментарием; сервер проверяет доступ к объекту. Поддержка MUST быть доступна по опубликованному email, встроенный helpdesk не требуется. Основание: FR-REP-1/3.

#### Scenario: Report submitted
- **WHEN** ученик жалуется на доступное ему упражнение
- **THEN** создаётся запись для reviewer с безопасно отображаемым комментарием.

### Requirement: Distinct-user threshold
Три жалобы разных пользователей за скользящие 7 дней MUST переводить упражнение в flagged и исключать из показа до ревью. Повторы одного пользователя MUST не увеличивать число разных авторов. Основание: FR-REP-2.

#### Scenario: Duplicate reporter
- **WHEN** один пользователь отправляет три жалобы
- **THEN** порог трёх разных пользователей не достигается.

#### Scenario: Concurrent third report
- **WHEN** конкурентные жалобы достигают порога
- **THEN** упражнение становится flagged один раз и недоступно новым показам.

### Requirement: Moderation outcomes
Reviewer/admin MUST исправлять, скрывать либо отклонять жалобу с аудитом; возврат в published требует валидного контента и ревью. Основание: FR-ADM-1, FR-EX-5.

#### Scenario: Restore invalid content
- **WHEN** reviewer возвращает flagged упражнение с невалидным ключом
- **THEN** публикация отклоняется, жалоба не позволяет обойти schema validation.
