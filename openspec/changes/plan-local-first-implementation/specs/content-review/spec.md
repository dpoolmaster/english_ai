## Purpose

Гарантировать выдачу только проверенных упражнений и дать редакторам управляемый процесс ревью, публикации и повторного контроля качества.

## ADDED Requirements

### Requirement: Schemas and publication states
payload/answer_key MUST иметь schema_version и проходить JSON Schema при сохранении и публикации. Сервер MUST проверять переходы draft/review/published/flagged/archived; ученику доступны только published. Основание: FR-EX-4/5.

#### Scenario: Invalid publication
- **WHEN** reviewer публикует упражнение с неверной схемой
- **THEN** публикация отклоняется с диагностикой, упражнение не попадает ученику.

### Requirement: Human review
Админка MUST предоставлять очередь, approve/reject/edit, ученический предпросмотр, горячие клавиши и массовые действия. Первые 100 упражнений каждого типа MUST полностью проверяться человеком; затем действует выборочный контроль ТЗ с обязательным ревью всех автоматических флагов. Основание: ТЗ 8.1, FR-ADM-1.

#### Scenario: Approved edit
- **WHEN** reviewer исправляет и утверждает упражнение
- **THEN** сохраняются автор, время и аудит, предпросмотр соответствует пользовательскому отображению.

### Requirement: Post-publication quality
После 50 попыток доля успеха ниже 15% или выше 98% MUST давать пометку пересмотра. Непубликованный контент MUST не показываться новым заданием даже из ранее собранной очереди. Основание: ТЗ 8.1, FR-EX-5.

#### Scenario: Flagged active item
- **WHEN** неотвеченное упражнение активного занятия стало flagged
- **THEN** сервер заменяет его доступным опубликованным либо сообщает о нехватке без штрафа ученику.

#### Scenario: Statistical anomaly
- **WHEN** после 50 попыток доля успеха выходит за пороги
- **THEN** упражнение отмечается на пересмотр без автоматической подмены ключа моделью.
