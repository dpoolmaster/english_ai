## Purpose

Обеспечить воспроизводимую проверку ответов, объяснимую обратную связь и ограниченное использование модели только для дополнительной проверки перевода.

## ADDED Requirements

### Requirement: Closed exercise scoring
Система MUST проверять mcq/cloze_choice по id, cloze_input по допустимым ответам, reorder по последовательности с частичными баллами, match по парам, flashcard по самооценке Again/Hard/Good/Easy. Закрытая проверка MUST не использовать LLM. Основание: FR-EX-1.

#### Scenario: Invalid answer structure
- **WHEN** отправлен неизвестный id варианта или повреждённая структура
- **THEN** запрос отклоняется без успешной попытки и изменения FSRS.

#### Scenario: Partially correct reorder
- **WHEN** порядок слов совпадает с ключом частично
- **THEN** возвращаются воспроизводимый частичный score и правильная последовательность.

### Requirement: Configurable normalization
Нормализация MUST обрезать и схлопывать пробелы, унифицировать апострофы, игнорировать завершающую пунктуацию и учитывать флаги регистра/сокращений. Настраиваемая опечатка в 1 символ допустима только для слов длиннее 4 букв и сопровождается подсказкой. Основание: FR-EX-2.

#### Scenario: Contraction flag
- **WHEN** I'm сравнивается с I am при разных значениях флага
- **THEN** эквивалентность применяется только при включённом флаге.

#### Scenario: Typo boundary
- **WHEN** ответ отличается одной разрешённой опечаткой
- **THEN** слово длиннее 4 букв засчитывается с подсказкой, короткое слово не получает этот допуск.

### Requirement: Translation fallback
translate_to_en MUST сначала проверять допустимые варианты детерминированно, при несовпадении использовать ограниченный квотой LLM. Ошибка модели MUST не становиться подтверждением корректности. Основание: FR-EX-1.

#### Scenario: Listed translation
- **WHEN** перевод совпал с допустимым вариантом
- **THEN** ответ засчитывается без внешнего вызова и LLM-списания.

#### Scenario: Additional check unavailable
- **WHEN** модель недоступна или дополнительная квота исчерпана
- **THEN** ученик видит контролируемый результат недоступности проверки без неподтверждённого успеха и списания.

### Requirement: Prepared feedback
После ответа MUST показываться результат, правильный вариант, готовое explanation_ru, правило и жалоба. error_type неверного варианта MUST записываться однократно. Основание: FR-EX-3.

#### Scenario: Tagged wrong choice
- **WHEN** выбран неверный вариант с error_type
- **THEN** показывается объяснение из карточки без генерации, повтор запроса не дублирует error event.
