## Purpose

Предоставить русскоязычный адаптивный учебный интерфейс с полноценной навигацией, частичными обновлениями и безопасным отображением пользовательского текста.

## ADDED Requirements

### Requirement: Direct pages and partial navigation
Каждый пользовательский маршрут MUST открываться прямой ссылкой как полная страница; запрос с HX-Request MUST получать соответствующий фрагмент. Обычные формы MUST сохранять базовый сценарий без обязательного JavaScript. Основание: ТЗ 7.1.

#### Scenario: Direct and partial request
- **WHEN** один маршрут запрошен обычным браузером и через HTMX
- **THEN** возвращаются соответственно полная страница и фрагмент без вложенного layout; успешный POST выполняет корректную навигацию или обновление.

### Requirement: Safe forms and errors
Ошибки полей MUST отображаться как при обычной отправке, так и при HTMX 4xx; 5xx MUST давать понятный общий ответ без внутренних данных. Пользовательский и модельный текст MUST автоэкранироваться, ответ тьютора не интерпретируется как Markdown/HTML. Основание: ТЗ 7.1, 9.1.

#### Scenario: Malicious text and invalid form
- **WHEN** форма содержит HTML/скрипт и не проходит валидацию
- **THEN** ошибка видна, безопасные значения полей сохранены как текст, скрипт не исполняется и stack trace не раскрывается.

### Requirement: Local assets and browser policy
Библиотеки пользовательского интерфейса MUST раздаваться локально с версиями; inline-скрипты запрещены. Все ответы MUST иметь CSP, HSTS, nosniff, same-origin referrer policy и microphone self policy; исключение стороннего скрипта ограничено SmartCaptcha на auth-страницах. Основание: ТЗ 7.1.

#### Scenario: Security policy
- **WHEN** запрашивается обычная страница, ошибка или фрагмент
- **THEN** присутствуют security headers, произвольный сторонний скрипт блокируется, локальные ассеты работают.

### Requirement: Russian adaptive learning interface
Интерфейс MUST поддерживать смартфон и desktop, русский язык и PWA-манифест; объяснения уровней A1–B1 русские, для B2 по умолчанию английские с русским по запросу. Основание: ТЗ 1.2.

#### Scenario: Narrow viewport
- **WHEN** ученик открывает занятие на смартфоне
- **THEN** ответ, обратная связь и навигация доступны без потери действий из-за ширины экрана.
