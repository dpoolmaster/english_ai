## Purpose

Разделить локальную готовность, подтверждение внешних интеграций и приёмку платного запуска измеримыми тестами, контентом, восстановлением и результатами пилота.

## ADDED Requirements

### Requirement: Automated release gate
CI MUST блокировать слияние при ошибках tests/vet/lint/govulncheck, неактуальном generated-коде или frontend build. Ключевые auth/billing/planner/exercises/placement MUST иметь покрытие >=70%; PostgreSQL проверяется интеграционно, adapters — контрактно, основные flows — Playwright. Основание: ТЗ 9.6.

#### Scenario: Stale generated code
- **WHEN** генерация Templ/sqlc/OpenAPI types меняет закоммиченные результаты
- **THEN** проверка актуальности падает, зелёная компиляция сама по себе не разрешает слияние.

### Requirement: Measured performance
Приёмка MUST измерить k6 150 сессий 10 минут: страницы p95 <=300 мс, закрытая проверка p95 <=150 мс, ошибок <=1%; первый токен тьютора p50 <=2 с. Результат MUST указывать окружение и реальные/fake providers. Основание: ТЗ 9.2/10.2.

#### Scenario: Mock passes but real provider is slow
- **WHEN** fake-нагрузка проходит, а реальный тьютор не достигает цели первого токена
- **THEN** внешняя метрика остаётся неподтверждённой, локальный тест не объявляется её доказательством.

### Requirement: Deploy and recovery before pilot
Перед пилотом MUST быть проверены deployment по тегу, откат образа с совместимой схемой, TLS, SSE без buffering, закрытые БД/метрики, non-root containers и алерты. Backups MUST шифроваться, храниться у другого российского провайдера: 14 daily/8 weekly; restore ежемесячно с RTO 4ч/RPO 24ч. Основание: ТЗ 9.3–9.7, этап 0.

#### Scenario: Restore drill
- **WHEN** backup восстановлен на чистом окружении
- **THEN** проверяются целостность, вход/прогресс и измеренное время; наличие файла dump само по себе не считается restore.

### Requirement: Legal and real integration prerequisites
До обработки реальных пользователей MUST быть проверены хранение в РФ, уведомление РКН, документы/согласие/контакты и лицензии. До запуска MUST быть проверены реальные оплата/чек/возврат, почта SPF/DKIM/DMARC и OAuth account takeover; ASVS L1 проходит ручную проверку. Основание: ТЗ 2, 9.1, приложение D.

#### Scenario: Fake payment acceptance
- **WHEN** E2E прошёл на fake payment provider без боевой проверки
- **THEN** локальный сценарий принят, но готовность реальной оплаты/чека/возврата не отмечена выполненной.

### Requirement: Authentication resource acceptance
Приёмка auth MUST включать 100 одновременных логинов с измерением памяти в заранее зафиксированном бюджете окружения; ограничение параллельного хэширования MUST сохраняться под нагрузкой. Основание: приёмка FR-AUTH, ТЗ 4.1.

#### Scenario: Concurrent login load
- **WHEN** выполняются 100 одновременных входов
- **THEN** измеренная память не превышает согласованный бюджет, одновременно вычисляется не более 4 хэшей, результаты и ошибки входа остаются корректными.

### Requirement: Cost and reliability acceptance
Перед платным запуском система MUST показывать фактические затраты на активного пользователя и расчёт выбранных тарифов: переменные затраты не выше 25% выручки и отсутствие убытка при полном выборе лимитов. Мониторинг MUST измерять целевую доступность 99,5%/месяц, 5xx ниже 1%, ошибки провайдеров ниже 2% при работающем fallback и жалобы ниже 3% показов. Месячные и долгосрочные показатели не считаются доказанными коротким тестом. Основание: ТЗ 9.3, 10.2–10.3.

#### Scenario: Full quota economics
- **WHEN** владелец задаёт цены тарифов и актуальные цены провайдеров
- **THEN** отчёт показывает обычный и предельный расход, превышение целевой себестоимости требует корректировки до запуска, а не скрывается усреднением.

### Requirement: MVP content and pilot
Первый релиз MUST иметь полный объём FR этапа 1, >=700 опубликованных A1–A2 упражнений, >=120 placement items и пилот 20–50 пользователей >=14 дней с метриками. Events MUST храниться локально без внешних трекеров: registered/email_verified/onboarding_done/placement_done/lesson_started/lesson_finished/paywall_shown/checkout_started/paid/chat_started/report_sent/reminder_sent/reminder_clicked; voice_used активируется на этапе 2. Основание: ТЗ 10.1/11.

#### Scenario: Generated but unpublished content
- **WHEN** создано 700 draft упражнений без ревью
- **THEN** контентный критерий MVP не выполнен.

#### Scenario: Pilot acceptance
- **WHEN** завершён минимальный пилот
- **THEN** сохраняется отчёт об активации, завершении, регулярности, конверсии и обнаруженных проблемах; критичные проблемы устраняются до платного запуска, неподтверждённые долгосрочные CEFR-метрики не объявляются достигнутыми.
